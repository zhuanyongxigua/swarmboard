# 编码与评审

## 修改前与实现

- 从 [文档索引](../index.md)选择最小阅读集，检查相关源码、测试与工作区改动。保留他人修改，不根据文件名或旧报告推断当前行为。
- 代码、注释、标识符、提交信息和代码块使用 English；解释性文档使用简体中文，现有英文用户文档保持英文。
- 保持可评审的最小改动；接口与状态变化同步对应主题契约，持久取舍按 [文档维护](../harness.md)记录。
- SQLite 状态更新、版本检查和追加事件保持事务边界；过期版本不能自动覆盖，不确定回执不能盲目重放。详细语义由 [架构](../architecture.md)、[事件工作会话](../event-workers.md)主责。
- 不把外部成员或个人 harness 的具体策略硬编码进通用内核；通过 [适配接口](../harness-adapters.md)和[正式准入](../external-collaborators.md)接入。
- 新建或实质修改脚本时，文件顶部用 1–3 行 English 注释说明为什么需要它；生成物和第三方源码除外。

## 界面改动

沿用 [界面契约](../collaboration-environment-ui.md)：控件有明确语义和可访问名称，操作范围可辨认；加载、失败、冲突和未确认写入有准确反馈，不能把前端反馈当作持久化成功。用受影响的真实浏览器路径验证交互及布局，不为小改动重跑无关矩阵。

## 评审与 Git 交付

先用简短说明解释问题、改后行为和方案，再检查正确性、状态／授权边界、兼容与失败路径，最后检查可读性。区分阻塞缺陷与可选优化，不为无关强化拖延既定交付。

- 分支从最新 `main` 开始，默认使用 `codex/` 前缀；工作树放在仓库之外，避免嵌套检出。
- 修改他人 PR 只追加修复，保留作者及原提交历史；未经授权不 rebase、强推或重写历史。
- 检查只包含本任务的 diff、敏感内容、适用验证和 `git diff --check`，再推送任务分支。
- 遵守主线当前 PR／CI 保护；解决真实审查讨论，不以关闭讨论或绕过保护代替修复。只有人类明确授权才合入；交付状态按 [发布规则](release.md)分别报告。
