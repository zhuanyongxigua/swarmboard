# 测试与证据规则

开发者同时负责实现、适用测试和文档。具体命令、已有覆盖与局限由 [测试说明](../testing.md)主责；本页只规定如何选范围和解释证据。

## 按风险选择

- 行为、接口、状态、权限或持久化变化时，新增或更新能判定目标行为的回归。修复缺陷优先保留修复前失败、修复后通过的证据；环境故障不能冒充有效红例。
- 纯文档、机械重命名或低风险视觉改动不制造重复测试；运行相关检查，复用未受影响的证据。先跑最小范围，只有新增风险、失败或未解疑点才扩大。
- 前端可见行为用真实浏览器检查；打包入口通过解压后的实际 stdio 服务验证；恢复与并发按真实边界选择协议、SQLite 或子进程故障测试。单一层级不能替代其他受影响层。
- 普通 CI 不调用真实模型，不接触用户看板、真实会话和生产数据。真实模型或实际宿主测试须有明确授权，保持隔离和原有审批，不因测试扩大访问范围。
- 保留失败与限制，不删断言、不以错误结果生成预期值，不重复运行只为掩盖不稳定问题。

## 文档与交付

文档改动运行 `npm run test:docs`、`npm run check:docs` 与 `git diff --check`。完整确定性检查是 `npm run check`；需要按主线保护执行的 CI 仍正常执行。

报告写清准确命令、目标版本、环境和结果；区分源码测试、替身、实际进程、模拟 MCP 宿主、真实桌面与真实模型。代码存在、测试通过、PR 合入、包已安装和成员实际消费是不同阶段，按 [发布规则](release.md)记录。

性能和成本结论必须来自已执行且可比较的实验；记录任务质量、耗时、token、费用、并发配置及失败。未执行的基准方案只能称方案，不因参与人数或进程存活推断协作效果。
