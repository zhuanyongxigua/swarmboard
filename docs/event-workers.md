# 事件驱动的平等同伴组织

[返回架构说明](architecture.md)

## 人类目标与内部协作

组织成员自行决定目标、范围、优先级、并行贡献和协作者；运行时不设一人一任务配额，不按整个人类目标串行，也不把 CLAIM 当作排他锁。成员完成一项贡献后重新读取全局目标与共享证据，再自主选择下一步。默认组织有三个平等 worker，初始人数可配置为 1–128，默认成员预算 maxSize 为 8（初始人数更多时至少覆盖初始数量）。成员可用 peer_request 按预算请求增加一位同伴；人类可通过版本化 pool_configure 扩容或调整预算，保留原成员与会话。运行时只负责容量、事件传递、持久会话和生命周期；不按任务数不断新增 worker，不安排中心 leader，不给同伴指定实现／评审等固定角色。多个目标共享同一个组织，同伴自行决定贡献范围、依赖顺序和整合方式。

任务面板保留人类提出的目标及验收状态，资源池保留人类登记的资源。内部子问题、工作范围和交接必须写在追加式共享面板中：用 CLAIM 声明贡献，用 MESSAGE 协商重叠，用 FACT/FAIL 分享证据，用 PATCH_SUMMARY 交付修改。后台池的 MCP 不暴露 task_create、resource_create、resource_update 或组织管理入口。已有全局 Swarmboard 插件在专用 App Server 中关闭，避免同伴误用不受该工具集限制的重复入口。这是可信本地协作接口的约束，不是对恶意拥有宿主访问权的客户端的隔离。

同一人类目标采用 participants，不设排他负责人。task_claim 表示加入；带 taskId 的局部 CLAIM 也会原子登记参与者并将 todo 置为 in_progress。每位活跃参与者均可携带当前版本与绑定身份更新目标，无需指定联系人。task_release 只退出本人；其他人仍参与时保持状态，最后一人退出才退回 todo/blocked。人类退回 todo 清空活跃参与者。局部贡献完成不等于目标验收完成；不得用内部任务卡代替协商。

## 项目绑定与首次启动

在已获人类授权操作该项目的聊天中调用 pool_configure：

```json
{
  "workspacePath": "/absolute/path/to/authorized/project",
  "size": 3,
  "maxSize": 8,
  "taskIds": [],
  "expectedVersion": 0
}
```

目录必须是存在的绝对路径。首次配置默认订阅全板的人类目标（省略 taskIds 或 taskIds:[]），以后新建目标会通知全体成员。非空列表只用于显式限定的兼容场景，不作为默认任务接入方式。不从任务正文推导目录授权，不以安装插件的目录作为默认业务项目。生产入口可以从可信 SWARMBOARD_PROJECT_PATH 配置或唯一既有事件 worker 的已授权目录初始化默认组织；全新安装仍需要绑定一次项目。多个既有独立 worker 不会被猜测合并。

有可执行目标（todo/in_progress）时才准备同伴和创建模型会话。Git 项目为每位同伴建立独立本地 clone、独立 .git 与分支，保存在数据库旁 workspaces/<poolId>/peer-N；只复制已提交文件，不复制未跟踪文件、.env 或本地导出数据。源目录的未提交修改不会自动进入 clone。非 Git 项目仅准备空隔离目录，所需资产须在已授权范围内另行交付。准备中断的目录不会被自动覆盖或删除，需检查后恢复。

组织有持久成员后不能更换源目录、缩窄订阅或改成另一组选定目标。显式 pool_configure(taskIds:[], expectedVersion) 可将旧的选定目标订阅扩展为全看板；省略 taskIds 的容量调整保留原订阅。扩展在同一 sidecar 事务中保留成员、会话和执行检查点并更新订阅，持久 outbox 补发此前漏过的未完成目标；原事件游标不回退，不重放已处理业务动作，暂停也不被解除。容量在原组织增长，同一成员 requestId 持久去重，重启重试不重复扩容；预算在创建前检查。当前不缩容、不删除成员历史。存在组织时 worker_register 拒绝游离成员。runtime_read 返回绑定、成员目录、threadId、事件游标、错误和组织状态。旧 worker_register/update/reconcile 保留供兼容和故障恢复；存在组织时旧独立 worker 不再同时执行，原身份和历史保留。

## 事件与消息

普通广播（CLAIM、FACT、PATCH_SUMMARY、非定向 MESSAGE）默认在静默 15 秒后合并投递；连续广播最多等待 60 秒。新建或修订人类目标等 OBSERVED、FAIL、定向消息保持即时投递资格，忙碌成员仍在当前回合结束后处理。已有每次工具返回的增量共享更新保持即时。这里仅调整通知时机，不限制贡献人数、角色、任务数量或自组织方式。

等待期间不推进确认游标、不删除或改写事件；截止时间依据已提交事件时间计算，重启不会重新开始等待。积压满一页时直接继续有界投递，避免后面的人类目标被窗口挡住。短通知中的长 detail 标记 detailTruncated，成员可用 context_read(after=entry.id-1, limit=1) 读取完整原文；同文不同 id 的记录都保留。运行时通知去重仍以已完成回合的持久游标为准，不将回合中途看到一条更新当成已完成执行。

宿主环境变量 SWARMBOARD_NOTIFICATION_BATCH_MS 调整静默窗口（0–60000 毫秒），设为 0 恢复即时广播；SWARMBOARD_NOTIFICATION_MAX_WAIT_MS 调整连续事件的最大等待（不小于静默窗口，最多 300000 毫秒，默认 60000）。无效配置拒绝启动。修改配置需要后台重新加载，任务、原会话和游标保留。runtime_read.notifications 返回实际窗口和下次等待截止时间。该实验不改变成员模型或思考深度，也不自动压缩或删除会话历史。

本轮采用相同十条事件、三个固定成员的隔离重放：即时模式产生 30 次执行替身回合，合并模式产生 3 次，每位成员收到同一组十个事件 id。此结果说明减少唤醒机会，不代表实际 token、费用、完成质量或真实模型耗时已降低相同比例；长期会话历史和定向交互仍会消耗上下文。

任务状态与共享事件在 SQLite 事务提交后，本地运行时监听数据库及 WAL，向所有相关平等同伴发送目标、CLAIM、FACT、FAIL、PATCH_SUMMARY 与消息；定向 MESSAGE 只发给收件人。同伴忙碌时事件持久排队。专用 MCP 每次成功工具调用的返回还附加新共享记录及继续／收尾控制信号，供回合中途获知同伴发现；不会抢占模型或正在运行的外部命令。

context_read 增量分页，context_search 按字面词搜索完整历史，而非只搜 board_read 最近 100 条。记录可能在工具附加更新与下一回合中重复出现，按 entry id 去重，不重复执行副作用。大量相关事件以有界批次处理；不要求逐条唤醒所有模型。30 秒恢复扫描仅检查持久数据，无可推进目标的空队列不调用模型；可推进目标长时间全员空闲时按下述有界兜底处理，不新建宿主定时会话。所有监听进程退出时不会凭空唤醒。

## 多目标发现与任务量边界

任务数量不决定成员分工，也没有一人一目标配额。对照 [Agensh 附录 A/B](https://arxiv.org/html/2609.26781v1#A1)，统一成员协议负责引导自主选择、协商、验证和整合；运行时只维护事件与共享状态。论文中的单一重建目标不直接证明本项目的多个人类目标场景，因此必须另外验证运行中新增目标、跨目标贡献和忙碌成员追赶。

专用成员 MCP 的 board_read/board_open 只返回前 20 个未完成目标摘要及 taskPage.hasMore/cursor，正文通过 task_read 读取；人类界面仍保留完整任务快照。task_list 默认包含 todo/in_progress/in_review/blocked，不按参与者过滤；limit 默认 20、最多 50，携带 after=cursor 继续分页，也可指定 statuses 或按正文和标题字面搜索。游标按不可删除任务行的插入顺序推进，修改任务、相同时间戳和时钟回拨不改变顺序。页面顺序不是任务优先级；收到状态修订或开始新回合时须重新发现目标，旧筛选游标不是状态变更订阅。

task_read(id, offset, limit) 返回目标元数据和 description/acceptanceCriteria 的正文片段；默认每个字段 4,000 字符，最多 8,000。textPage.hasMore 为真时用 nextOffset 继续，并将首次返回的 version 作为 expectedVersion；遇版本冲突从零重新读取，避免混用不同修订。分页和截短都有显式标记，不以摘要代替完整验收条件。回合内附加共享更新及最近上下文也压缩长 detail，标记 detailTruncated；用 context_read(after=entry.id-1,limit=1) 按需展开原文，持久记录不被改写。

运行时状态判断只查询目标 id/status/version 等元数据，不再反复加载所有任务正文。空闲恢复信号只带计数和最多 20 个目标样例，goalIdsHasMore 标明省略；成员通过 task_list 查看全局目标，样例不构成分配或执行顺序。

以上解决有界发现和事件追赶，不承诺无限任务吞吐或所有成员立即中断当前工作。忙碌成员的普通事件在下回合交付，MCP 返回可附带回合内更新；显式暂停、审批暂停、错误或不确定投递仍须先按原恢复门禁处理，事件不会因此被分配给某个排他负责人。全板可见性也不扩大已授权项目、网络或生产权限。确定性压力回归与小规模真实模型验收的证明范围分别记录在验证台账，不能相互替代。

## GitLab CI 持久订阅

等待 CI 前调用 pipeline_watch，提供现有人类 taskId、pipelineId 和完整 40 位 sha。host/project 只从人类授权源项目的 Git origin 读取，不接受正文里的任意 URL；origin 凭据不进入订阅。运行时通过既有 glab 登录执行只读 pipeline API，原始响应、stderr 和凭据不进入模型或共享记录。

订阅持久保存在 sidecar；每次最多查询四个到期流水线，每次请求十五秒超时，running 最早三十秒后再查，失败最早六十秒后重试。运行期间不调用模型；终态或首次 manual 发布一次共享证据，全体相关成员在原会话收到。三次查询失败或 SHA 不匹配发布脱敏 FAIL 并停止订阅，显式 retry 才重试。较新的 pipeline 取消旧订阅，迟到结果与停止后的结果不发布。事件先持久化 outbox、看板事务去重，再确认；崩溃后恢复原信号。

有效 CI 等待不消费该目标的空闲提醒预算，也不掩盖其他可推进目标。结果只证明该 pipeline 的 SHA/status；同伴仍须核实 MR 最新 head、review、验收与人类合入授权，运行时不自动合入或设置完成。当前仅有 GitLab pipeline 适配器，其他等待依靠共享消息、人类状态或有界空闲恢复。全部监听进程退出后仍不能接收事件。

## 内部执行与空闲兜底

当前执行策略为 `INTERNAL_ONLY`：模型工作只在已绑定的官方 Codex 会话与既有 peers 之间完成，暂不启动、续发、监控外部 harness，也不嵌套创建新的模型 worker。旧任务正文或工作包里的外派要求被此策略覆盖。正常构建、测试、Git 与已授权 CI 不受此模型执行策略限制。提示和 shared-worker skill 明确该约定；这不是阻止恶意宿主进程调用其他程序的安全沙箱。

无需给每张任务卡创建定时器。运行时原有 30 秒数据扫描同时检查持久化的组织空闲检查点：仅在存在 todo/in_progress、至少一名可派发（启用且 idle）成员、没有可派发成员的待处理事件且无任何未核实投递时，连续空闲十分钟才向一名可派发 peer 写入定向 `IDLE_RECOVERY`。被保护成员（人工或审批暂停、error、未核实投递）不参与也不阻塞该恢复，其旧未读游标不会永久压制健康子集；下一次提醒在可派发成员中轮换；同伴自行选择贡献和协商，不由运行时指定实现／评审角色。回合执行期间重新计空闲时间，不因长构建或忙碌回合重启模型。

目标版本或人类组织控制版本变化会重置提醒预算。心跳、应答、FACT 等自报信息不等同验收进度，不重置预算。最多两次提醒，若再空闲十分钟且目标无修订，记录 `IDLE_ATTENTION` 并停止自动空闲提醒；界面显示需要处理与“重新检查”。该按钮以最新版本恢复组织并重置预算，不自动解除成员审批暂停或不确定投递。运行时不把卡片擅自改为受阻／完成；同伴须发布具体前置缺口，由活跃参与者根据共享证据将真正等待的任务设 blocked/in_review。新的相关事件仍正常投递，人工停池仍阻止新回合。

检查点和待发信号在 sidecar 中先持久化，信号以不可变身份写入共享面板，并在同一个看板事务中去重，最后确认检查点；崩溃后可重发同一信号，不重复创建消息或聊天。扫描串行化，单 owner、原会话、投递核查与暂停门禁继续适用。顶部分别显示实际成员数、执行数、空闲／等待／需要处理，不再把“有目标”直接标作“协作中”。

## 停止、等待与恢复

成员容量通过版本化 `pool_configure` 的 `maxSize` 在线调整，保持当前 `size` 不变即可只调整上限，不创建新成员，也不需要重启监听器。达到配置上限后，“增加成员”按钮置灰；鼠标悬浮或键盘聚焦按钮外层时，显示“已达成员上限（N 人）”，其中 N 来自当前配置。成员容量不规定同伴的任务分工。

- 全部订阅目标 done/canceled：安全收尾后 completed，关闭空闲 App Server 进程；会话历史、代码和证据保留。出现新的人类目标后复用原成员与 threadId。
- 只剩 blocked/in_review：waiting，等待新事实、消息或人类状态变化；不把受阻伪装为完成，也不靠模型轮询。
- 顶部停止按钮／pool_control：携带最新 expectedVersion 与 enabled=false，阻止新回合，已提交回合收尾。每次 MCP 工具返回提示停止；停止后的业务写入被拒绝，仍允许发布收尾记录、心跳和释放资源声明。不能取消已经发生的外部副作用。
- 恢复携带最新版本与 enabled=true。暂停、审批或不确定执行状态不会因过期检查点被覆盖。会话打开期间发生停止，也会在提交模型回合前再次核对。

任务与共享上下文仍在 board.sqlite；成员、组织及检查点位于 board.sqlite.runtime.sqlite。备份须包含两者及一致 SQLite 快照，以及独立代码目录。schema v5 将旧 assignee 迁为参与者并清空排他归属，保留任务版本及追加历史。旧二进制拒绝新 schema，不能直接降级打开新库，回退须恢复升级前一致快照。一块看板仅一个存活 owner 投递，不因心跳晚到就抢走执行权。

投递先持久化 deliveryId/待确认游标/threadId/turnId；只有成功完成才推进游标。进程退出或结果丢失保持 uncertain，不盲目重放。worker_reconcile 只读核对保存的执行：完成则确认；明确失败则 error，检查残留工作后恢复；仍运行或未知继续等待。无法核实的回合会阻止组织虚报完全停止。审批暂停和原因在核查完成后继续保留，只有显式恢复才继续工作；过期检查点不能覆盖较新的暂停及原因。

0.8.2 增加持久化 deliveryPhase：opening 在恢复会话前记录，submitting 在调用 turn/start 前记录，running 在收到 turnId 后记录。已有 threadId 的恢复超时属于连接失败，尚未提交模型回合，保留游标与原身份并置 error，不再标成业务执行不明。重启核查只有在 opening、已有 threadId 且没有 turnId 的证据成立时，才允许转为可显式恢复的 error；缺少阶段的旧检查点仅兼容精确的旧 `thread/resume timed out; delivery outcome is unknown` 诊断。submitting/running、无此证据的旧检查点及新建会话确认丢失仍保持 uncertain，不以“没有 turnId”推断未执行。

0.8.3 区分启动与普通请求预算：thread/start 与 thread/resume 要等待 MCP 初始化，默认最多 90 秒；initialize、turn/start 确认和只读请求仍是 30 秒，不延长模型提交的不确定窗口。真实六成员并发恢复实验测得 42–50 秒，原 30 秒预算会在依赖完成前结束连接；这与 active writer 是两种不同故障，重启客户端不能替代合理的启动预算。swarmboard_worker 设为 required，缺少协调 MCP 时启动失败，不能带着缺失的共享工具进入模型回合。保持全部成员并发、自组织及原身份，不增加任务定时器、中心分工或盲目重试。

如果官方 App Server 返回 active writer，说明另一个连接仍持有该会话。运行时显示明确的连接占用原因，不强杀桌面进程、不删除锁、不换会话或盲目重试。先暂停组织，关闭占用的聊天视图或由用户正常重启占用客户端；确认占用已释放后，对旧 uncertain 检查点执行 worker_reconcile，再用最新版本显式启用 error 成员，最后恢复组织。恢复不推进未处理事件游标，不改变目标状态。若客户端仍持有写入权，恢复会再次停在 error，需要解决连接生命周期，不能宣称业务已恢复。

## 执行与权限

### 人类宿主的单任务执行例外

默认仍为 INTERNAL_ONLY。宿主在直接获得人类授权后，可通过根 MCP 的 task_execution_configure，为一个现有人类目标保存带 expectedVersion 的项目读取路径、独立执行目录、Zcode 执行和 monitoring 例外。授权与 poolId 绑定，持久保存在运行时 sidecar；不修改组织主项目、成员、角色、任务状态或事件游标。只有记录中的目标适用，其他目标保持原边界。

成员 MCP 只提供 execution_grants_read，不提供配置入口；可信运行提示与工具返回携带当前授权。任务正文、共享消息和 agent 自报均不能生成授权；终态目标、暂停组织、撤销记录或订阅不匹配不会返回有效授权。记录不扩大操作系统沙箱、不自动批准工具、不授予生产权限，也不证明 Zcode 或监控工具已可用。真正缺少工具须单独报告，不得以新会话或换入口绕过拒绝。

monitoring=true 仅允许该目标的外派跟进按 use-external-harness 建立或复用必要监控，成员自行商定参与方式；不恢复全局定时认领，不重复派工，不将观察者固定成任务主管。撤销后停止新增外派操作，已发生的工作须正常交接，不能把撤销当作取消外部副作用。人类工具入口属于本机受信任宿主面，不是面向不受信任远程用户的认证系统。

通过官方 codex app-server --stdio 启动和恢复，使用正常 CLI 登录及模型配置。程序不读取订阅 Token，不使用私有桌面 RPC/CDP。每个 worker 使用自己隔离目录的 workspace-write 与 on-request；不复制凭据、不扩大到所有项目、不自动批准权限请求，也不通过换 harness 绕过拒绝。当前暂停外派；远程机器和生产变更仍需要各自可用工具、授权和验收；唤醒成功不是业务已完成。

子 MCP 关闭运行时，避免递归创建组织。原生定时兼容接口仅用于旧记录管理；生产事件入口的 automation_ensure 不返回创建定时会话提示。旧宿主自动化要通过官方工具暂停／删除并回读，插件不私改宿主数据库。运行时通常随 MCP 服务存活，也可由同版本入口 --event-runtime 独立监听，使用相同 owner 保护。升级时先版本化暂停组织并等所有执行收尾，退出旧监听器，再通过官方 CLI 安装并启动新版、核对绑定后恢复。安装可能替换旧版本缓存路径，不能让仍需启动子 MCP 的旧 owner 在安装后继续接收新回合；仅安装成功不代表内存中的旧代码已接管。不支持跨机器路由或系统登录后自动启动。

## 验证

确定性集成测试覆盖三同伴共享一个目标、消息传播、独立检出、停止竞争、完成后停止与新目标复用；MCP 测试覆盖后台工具限制及工具附加消息；浏览器测试覆盖组织停止／恢复且不改变人类任务数。它们不证明模型实际遵循协作规则。

构建后显式执行 node scripts/verify-pool-runtime.mjs --live，使用正常模型、三个真实会话及独立 Git 检出，对同一个合成目标自主声明、定向讨论、交叉复核。根验收后设置目标完成，检查组织自动停止，任务始终一张、资源为零。该检查调用真实模型，不放进普通 CI，不操作真实 MR、开发机或生产。实际结果与边界见 [验证记录](verification.md)。
