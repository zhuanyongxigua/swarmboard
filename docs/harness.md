# 研发入口与文档维护

本仓库采用短入口、按需阅读、唯一主责及机械反馈的文档结构。目录按实际信息量增长，不为模板建立空的需求、规格、计划或过程归档体系。取舍见 [ADR-0001](decisions/ADR-0001-repository-documentation.md)。

## 分层与主责

| 层 | 位置 | 保存什么 |
| --- | --- | --- |
| 研发入口 | [AGENTS.md](../AGENTS.md)、[CLAUDE.md](../CLAUDE.md) | 稳定边界、一级地图；Claude 入口仅映射 AGENTS |
| 阅读导航 | [index.md](index.md) | 任务到最小必读文档集的路由 |
| 产品与架构契约 | [architecture.md](architecture.md)及现有主题文档 | 状态、范围、接口、失败语义和依赖方向 |
| 研发规则 | [rules/](rules/README.md) | 编码、评审、测试与发布约定 |
| 技术取舍 | [decisions/](decisions/index.md) | 背景、决定、后果及替代关系 |
| 验证证据 | [verification.md](verification.md)及其可定位产物 | 带版本、环境和限制的实际结果 |
| 当前工作 | Swarmboard 的任务和共享上下文 | 人类目标、贡献、即时进度与交接 |

运行时成员协议继续由 [shared-worker](../skills/shared-worker/SKILL.md)维护；[看板提示词](board-prompt-settings.md)是用户配置。开发指南不能成为覆盖运行时授权或厂商内置指令的另一入口。

## 同步与记录门槛

- 行为、接口、Schema、状态机或恢复语义变化时，同步修改对应主题文档；不要把计划中的功能描述成当前能力。
- 持久架构、数据、授权、安全或发布取舍才写 ADR；小型修复、改名和格式调整不逐条建记录。被替代的决定保留并链接新决定，不改写历史。
- 新增或移动文档时更新相应索引与入链；只有一级入口改变才调整 AGENTS。详细清单留在主题索引。
- 测试说明负责命令和覆盖边界，测试规则负责选择原则，验证记录负责实际结果；不复制同一测试矩阵。
- 不保存完整聊天、推理过程、用户数据库、凭据或个人会话路径。验收资料只保留可评审摘要和必要来源。
- 发现陈旧声明时修复本次涉及的主责位置，不借机全仓重排；临时故障与实时人数不写成长期产品规则。

## 可执行检查

`npm run check:docs` 检查 CLAUDE 仅含 `@AGENTS.md`、AGENTS 不超过 8 KiB 且链接必要一级入口、README 可达文档索引、本地链接／Markdown 标题锚点可定位，以及全部 `docs/**/*.md` 可从总索引到达。`npm run test:docs` 用隔离 fixture 验证坏链接、锚点、入口漂移与孤立文档会失败；两者接入 `npm run check`。

检查器处理 Markdown 行内链接、引用链接定义和图片路径，忽略代码块及外部 URL；不请求网络、不验证外部网页可用性，也不判断文档与实现语义一致或证明真实安装。文件名与命令必须对应当前仓库，不能把不可访问的本机私有路径当作可移植链接。
