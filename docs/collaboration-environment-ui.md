# 统一设置界面

看板只保留任务管理与共享面板两个顶层页签。右上角齿轮是统一设置入口，取代原连接文字与刷新图标；设置使用原生模态窗口，可通过关闭按钮或 Escape 关闭并将焦点返回入口。设置中的“重新读取设置”读取最新看板和配置，保留未保存草稿与版本冲突保护，不自动重放未确认写入。

设置按钮保持等宽等高与圆形边界，普通指针下为 34 像素，触控指针下扩大为 44 像素；触控最小点击高度不能只拉长按钮的纵向尺寸。齿轮图案使用居中的对称轮廓，避免图案本身纵向偏长。

任务页不渲染总数横行及其工具条容器，三栏直接占用任务面板顶部，不保留工具条高度或内边距。各列状态计数、错误提示与滚动保留；共享面板的记录标题及只读工具条继续显示。

会话定时检查由 CLI 适配层负责，面板不展示旧核心空闲检查的下次时间、检查次数告警或“重新检查”入口；历史兼容响应中的 watchdog 字段不作为当前调度事实。成员错误、CI 等待／错误、安全收尾状态和后台停止／恢复维护接口仍保留，不由旧空闲检查状态触发恢复。

面板不提供手动创建任务的按钮、菜单、空态、快捷键或表单。任务编辑状态必须携带已保存任务，提交仅调用 `task_update`；UI 操作类型及分发均不包含 `task_create`。人类仍可在聊天中提出目标，由受信宿主通过既有 `task_create` 登记，服务端与主聊天 MCP 创建工具保留。这是界面能力收缩，不新增对恶意 MCP 客户端的安全隔离。已有任务详情、编辑、状态拖拽与原生讨论保持可用；内部子问题仍记入共享上下文。

设置只包括成员上下限、系统提示词与用户提示词。成员上下限从当前组织读取，独立保存到正式 `pool_capacity` / `POST /api/pool/capacity`，输入必须是 1 到 128 的整数且最少不大于最多。保存携带表单读取时的版本；版本冲突保留草稿，重新读取并核对后才能保存。实际人数与正在收尾人数仍由原概览和容量状态展示，保存新目标不冒充人数立即达标；收缩不强杀在途工作。

系统提示词直接沿用原个人偏好的数据、版本、来源与接口，不创建第二份可写副本。用户提示词使用独立 `user_prompt_read` / `user_prompt_write`，HTTP 为 `GET` / `PATCH /api/user-prompt`。两者均显示当前保存值、版本、来源、更新时间，具有独立草稿、保存与显式清空操作。清空保存新的空版本；后台读取较新版本保留脏草稿并要求显式核对，不自动覆盖或重试。保存请求在途禁止重复提交。

“系统提示词”和“用户提示词”是看板配置名称。两者通过正式成员后续回合的指令快照机制加载，不声称覆盖厂商内置 system 指令、工具审批或项目授权；它们本身不提供执行授权。每轮原子快照与提交前复核的服务端合同见 [board-prompt-settings.md](board-prompt-settings.md)。

资源名称、用途、能力、访问与共享约定由用户提示词统一维护，界面不再提供“原资源记录”、资源列表、创建／编辑表单或管理导航。占用说明与协商通过共享面板发布。旧资源与使用记录保留为历史兼容数据，共享记录中的资源引用只显示历史名称，不跳回管理入口；它们不再是当前资源配置来源。迁入现有资源须由人类明确要求，经受信宿主按用户提示词的独立版本写入并核对，保留已有文本；不自动解析、同步或重复导入。用户编辑或清空后，不从旧资源记录自动补回。

浏览器回归覆盖新入口、两类提示词独立更新/清空、CAS 草稿保护、容量非法输入与冲突、历史记录保留、键盘关闭/焦点返回和窄屏。中英文独立网页和 MCP 嵌入回归核实无旧资源入口、用户提示词保存／清空／重开不回灌及历史引用只读。组合回归使用隔离真实 HTTP/SQLite，模型派发被禁止。README 双语图片由同一实际界面与合成数据生成，不能据此宣称正式桌面安装或模型实际遵循指令已经验收。

任务回归通过隔离 HTTP fixture 或受信宿主 MCP 预置目标，分别覆盖中英文独立网页及 MCP 嵌入面板：无创建按钮或新建对话框，不产生 UI 创建请求，同时核实已有任务编辑、拖拽与讨论。测试不保留浏览器手动创建路径。
