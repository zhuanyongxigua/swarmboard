# 测试分层

目标是分别证明规则、存储、协议和界面行为。源码里有测试、CI 执行了测试、以及真实客户端验收是不同证据；当前实际结果见 [verification.md](verification.md)。

| 层 | 命令 | 要证明的行为 |
| --- | --- | --- |
| 领域/单元 | `npm run test:unit` | 输入验证、状态、归属、版本冲突、资源共同使用 |
| SQLite 集成 | `npm run test:integration` | 真实事务、迁移、失败回滚、重开持久化、事件追加约束 |
| HTTP 黑盒 | `npm run test:api` | 实际启动的服务、路由、错误状态、认证、跨客户端变化 |
| MCP 协议 | `npm run test:mcp` | 官方 SDK 客户端的初始化、工具发现与调用、UI 资源、错误和增量游标 |
| 桌面插件打包 | `npm run package:desktop` | 构建自包含服务、界面、manifest 和 skill；成功打包本身不证明客户端已安装 |
| 桌面便携包协议 | `npm run test:desktop` | 先打包，再从 ZIP 解压到新临时目录，用官方 SDK 启动真实 stdio 子进程，验证工具、资源及持久化 |
| 浏览器 | `npm run test:e2e` | 真实服务和数据库上的任务分列、拖动及键盘改状态、双会话编辑冲突、资源声明与刷新持久化 |
| 完整检查 | `npm run check` | lint、类型、服务构建、桌面打包、覆盖率和浏览器测试串联 |

`npm run test:coverage` 执行全部 Vitest 套件并检查核心服务覆盖率门槛。覆盖率不能代替协议与浏览器行为验证；前端主要通过浏览器路径验收。CI 应通过 `npm ci` 使用锁文件，并安装浏览器后执行同一完整检查。

直接运行 `test:mcp`、`test:coverage` 或 `test` 前，需要先执行 `npm run package:desktop`，因为桌面套件验证实际 ZIP 而不是源码模拟物。`test:desktop` 和 `check` 已自动包含打包步骤。`src/index.ts` 与 `src/stdio.ts` 是真实子进程入口，不计入进程内 V8 覆盖率；它们的启动、协议和退出行为由黑盒测试单独证明。

所有数据均为合成数据，使用隔离数据库和临时端口；测试不访问真实开发机，也不调用模型。并发测试验证版本与原子事件，不能据此声称实现了真实机器隔离。XSS、非法输入和过期写入属于可观察的边界测试。

浏览器回归还检查无类型表单的新资源创建、旧资源编辑不覆盖已有类型与能力、两条共享使用声明分别释放，以及只读共享记录的文本转义。两个独立浏览器会话同时编辑同一任务时，过期写入必须被拒绝，草稿保留，用户显式载入最新内容后才能再保存。

本地模拟宿主用来验证 MCP Apps 桥接、iframe 沙箱中的表单提交以及嵌入时不访问 HTTP 开发接口，是受控协议测试；它不等同于 ChatGPT 已安装、真实宿主权限批准或插件商店审核。真实多 Agent 的产出质量与成本需要单独实验，不属于确定性回归测试的结论。

桌面套件通过官方 SDK 启动真实子进程，验证工具和 UI 资源。它从 ZIP 解压到新临时目录，使用隔离数据库、与源码无关的 cwd、没有 node_modules 的目录启动，检查 `${PLUGIN_ROOT}`、重启持久化、双进程首次初始化与认领竞争。macOS 临时路径符号链接和 SQLite WAL 初始化锁均包含实际失败后修复的回归证据。MCP 元数据存在及官方 CLI 安装成功不代表实际客户端已显示侧边栏，后者必须在真实桌面宿主验收。

原生讨论回归通过模拟桌面宿主检查实际 `ui/message` 出站信封，确认 `target: active`、`send: false` 扩展元数据没有被 SDK 基础 schema 丢弃。测试覆盖已有草稿保留、仅显式点击触发、选中任务只引用已保存版本、宿主不支持或拒绝时不降级为立即发送，以及完整数据库状态无变化。移动端即使声明消息能力也禁用此入口。`planning_partner` 通过官方 MCP 客户端发现和读取，检查讨论与摘要不构成写入授权，读取 prompt 后数据库保持不变。

这些测试不调用模型，不证明模型一定遵循规划约定，也不证明真实 ChatGPT 桌面版的面板位置、模型菜单、权限菜单或草稿交互；这些需要真实宿主验收。

双语文档截图由实际界面（英文 `?lang=en`、中文 `?lang=zh-CN`）和对应语言的隔离示例数据生成。截图脚本对英文视图检查可见文字无中文、文档语言一致且无横向溢出。浏览器回归验证英文表单真实保存、状态更新、切换中文后原始用户输入保持不变；便携包回归检查两份 README 各自引用三张对应语言的图片，解压后文件存在。

桌面启动回归还覆盖 GUI 精简 PATH：从干净 ZIP 解压，在没有 Node 与外部 shell 命令的 PATH 下，通过带空格的隔离 NVM 路径发现实际运行时，完成真实 MCP 初始化、工具发现与 HTML 读取；无效显式运行时必须以 127 退出，仅输出 stderr 诊断。macOS/Linux 执行这些 POSIX 测试；Windows 使用原来的直接 Node 启动配置。
